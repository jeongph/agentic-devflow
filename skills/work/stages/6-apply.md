# 6. apply — 리뷰 반영

## 입력

- `리뷰 결과` (5-review 출력)
- 검증 명령 (plan 단계 또는 `review` 사전 확인에서 확정한 것. 없으면 이 단계에 들어오지 않는다)
- 설정 `simplify`, `review_model`
- 이번 사이클의 리뷰 루프 횟수 (재개했으면 이슈의 정본 `review` 마커 코멘트에서 읽는다. 없으면 0)

## 절차

1. **치명·중요 항목** — 항목마다 해당 코드를 열어 지적이 맞는지 확인한다.
   - 맞으면 고친다.
   - 틀렸거나(리뷰어가 맥락을 놓침) 범위 밖이면 고치지 않고 이유를 적어 "미반영"으로 남긴다.
   - 리뷰어의 말을 확인 없이 따르지 않는다. 리뷰어도 코드를 잘못 읽는다.

2. **제안 항목** — 목록을 보여주고 반영할 것을 고르게 한다. 사용자가 고른 것만 반영한다.

3. 반영 후 검증 명령을 실행하고 통과하면 커밋한다. 성격에 맞는 타입을 쓴다 (`fix:` 버그, `refactor:` 구조, `test:` 테스트 보강). 검증이 실패하면 고친다. 실패한 채 커밋하지 않는다.

4. 치명·중요를 하나라도 반영했으면 **5-review를 다시** 돌린다. 고친 코드가 새 문제를 만들 수 있다.
   - 루프는 이번 사이클 통틀어 **최대 3회**. 재개해도 카운터는 이어진다.
   - 중간 회차는 반영한 항목과 관련된 에이전트만 돌려도 된다. 단 **"치명·중요 없음"으로 루프를 끝내는 마지막 회차는 전체 선택표대로** 돌린다. 축소된 재리뷰 결과만으로 통과를 선언하지 않는다.
   - 3회 후에도 치명·중요가 남으면 잔여 목록과 함께 사용자에게 넘긴다. 무한 루프로 토큰을 태우지 않는다. 이때 잔여 목록과 루프 횟수를 이슈 코멘트로 남긴다 (draft 승인 후):
     ```
     <!-- agentic-devflow:review -->
     ## 리뷰 잔여 항목 (3회 후)
     - [code-reviewer] … — `파일:라인`
     ```
     이 코멘트는 ship 단계가 PR을 만들기 전에 확인한다. 잔여가 없으면 이 코멘트를 남기지 않는다 (리뷰 완료 마커는 두지 않는다).

5. 치명·중요가 없으면 설정 `simplify`가 true일 때 `references/review-agents.md`의 "정리" 절차를 **1회** 수행한다. 워킹 트리가 깨끗하지 않으면 건너뛰고 알린다.

## 게이트

- 제안 항목 선택 (2).
- 3회 초과 시 사용자 판단, 잔여 코멘트 draft 승인 (4).

치명·중요 반영은 게이트 없이 진행한다. 리뷰를 요청한 시점에 반영도 위임된 것으로 본다. 단, 미반영 사유는 반드시 보고한다.

## 출력

- 반영 내역 (항목 → 커밋)
- 미반영 항목과 사유
- 최종 검증 결과 (실행한 명령 그대로)
- 리뷰 루프 횟수, 잔여 치명·중요 (있으면 코멘트 URL)
- 정리 수행 여부 (수행·건너뜀·되돌림)
